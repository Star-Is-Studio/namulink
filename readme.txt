개요

 - 아동발달센터(자라는나무 대전) 웹 기반 통합 관리 시스템

    - 추후 안정적 웹 작동 확인 후 타 아동발달센터 임대 사업 확장

    - 아동별 치료 가이드 AI 탑재

    - 치료사 음성으로 치료계획서 작성하면 텍스트로 정리 기능 지금 가능할ᄁᆞ요?

 - 이름 확정: 나무링크 / 희망 도메인 namulink.kr

 - 대상: 센터 직원(관리자·행정·치료사) + 학부모

 

기술 구성

 - 순수 HTML + localStorage로 시작 → Supabase(서울 리전, RLS) 하이브리드 동기화로 전환

- 개발: Claude Code, 배포: GitHub Pages(jet73kyj/namu-link, Private), 향후 Vercel

 - 7개 테이블(children, payments, therapists, voucher_data, intake_list, assessment_tokens, initial_assessments), 실데이터 3,397건 업로드 완료

 

 

구축된 기능

-연령대별 초기상담지 4종(19~60개월) + 토큰 기반 학부모 접근

-신규아동~종결까지 상태별 통합 아동관리, 아동 프로필 페이지

-유입경로·지원사업 유형 통계, 관리자번호 자동 부여

-납부·바우처·치료사 관리, HWPX 정부 서식 15종 변환

 

 

설계했으나 미구현

-직원 로그인(권한 3단계: 관리자/행정/치료사), 모바일 PWA

-공지사항, 자료실, 학부모 포털(일정·결제내역·치료일지), 내부 메시지, 카카오 알림톡

 

현재 상태

-저장 불안정 및 아동명 수정 시 중복 생성 버그 → ID(UUID) 구조 문제로 진단

-개발자 지인에게 코드 품질 지적을 받은 후, 현재 배포본을 역설계한 엑셀 설계도 기반으로 재설계 진행 중 (개발자 인계 목적)

1. 아동관리 (children.html, child-profile.html, child-form.html)

등록: 이름·생년·부모연락처·주소·담당매니저·상태(치료중/종결/휴식) + 다중 치료(therapies[])

치료 항목별: support(치료지원 언어/작업, 방과후, 발달재활, 센터비용), 치료사, 요일(cycle), 시간(timeSlot), 회기·단가(fee), 개시일/종결일, 휴식월(pausedMonths), 인수인계(handoff)

feeType: 소득분위→본인부담금 매핑 (다형/가형 등) → 발본 자동 세팅

중복 아동 병합: merge-duplicates.html, cleanup-children.html, merge-by-managerId.html

동일 이름+생년 sibling entry 처리: 여러 지원유형별로 record 를 분리 저장

 

제가 원하는 주 기능

신규아동 관리 > 유입경로, 상담일, 평가일정, 고정치료 또는 종결(종결 사유)등을 수집하여 다음년도 사업 계획 반영

과거 종결 및 현 진행 아동의 개인 모든 기록을 한번에 볼수 있었으면 좋겠음

 

그런데 몇 년 사용할 경우 평가보고서등 기록이 많아 로딩이 지속될 가능성 개인정보 관리 또는 데이터 관리등의 문제가 생기는지 궁금

정기적으로 년마다 별도 공간에 데이터를 저장해야 하는지 궁금?

 

2. 아동스케줄 (calendar.html)

자동 생성 기준: 납부관리 데이터를 기준으로 월 스케줄 생성

회기 규칙:  자동 아동 5주차 = 5회, 4주차 = 4회

            고정 아동 월 3~4회 주차 상관없이 고정 : 1주 · 2주만 선택 가능

보강 표기 자동화:

발추(발달재활 추가) 명단이 있는데 해당 월이 4주차인 경우 → 보강 표기

치료사 휴무일(공휴일/개인휴가/센터 휴관)에 걸린 회기 → 보강 표기

평가 일정: assessment_events — 신규상담에서 등록 → 캘린더 노출

월간·주간·일간 뷰 전환, 치료사별 필터, 아동 클릭 시 프로필 이동

 

치료사관리에서 해당 치료사 휴가 표기하면 해당 수업 휴가로 표기되면서 보강 필요 탭에 명단 생성

- 스케줄 일정에서 아동이름 클릭하면 결석 처리 및 보강일정 기재

보강일정 기재 시 해당일자에 보강일정 표시

- 치료사 인수인계 시 아동명 이름 뒤에 한달동안만 인계 표시

치료사관리에서 치료사 일정 기입 시  스케줄에 미표기

 

이벤트와 휴무 보강을 별도로 나누지 않고  함께 표기 / 전월 미진행된 수업 다음월 보강탭에 표기

기존 버튼 영역 우측(또는 별도 탭 영역)에 아래 3개 탭을 항상 표시해주세요.

[ 제공계획서 ] [ 중간평가보고서 ] [ 종결평가보고서 ]

• 기존 저장·인쇄·학부모 전달 버튼처럼 월이 바뀌어도 매달 동일하게 표시되어야 함

• 탭 클릭 시 해당 문서 작성 화면으로 이동



2. 제공계획서

• 정부 공식 서식 양식을 그대로 사용 (임의 변경 없음)

• 문서 내용을 언제든지 수정·저장 가능해야 함

• 내용 변경 시 수시로 업데이트할 수 있는 구조 (1회성 작성이 아닌 지속 편집 가능• 한 문서로 관리)

• 인쇄 / PDF 저장 기능 포함

 



3. 중간평가보고서

• 탭 클릭 시 해당 보고서 작성 화면 제공

• 작성 후 저장·수정 가능

• 인쇄 / PDF 저장 기능 포함

 



4. 종결평가보고서

• 탭 클릭 시 해당 보고서 작성 화면 제공

• 작성 후 저장·수정 가능

• 인쇄 / PDF 저장 기능 포함

 

 

우리는 발달재활서비스 1개 사업을 진행하여 서식은 한개이지만, 타기관의 경우 다양한 사업진행으로 서식이 다양한 사업별로 선택하여 서식을 사용할수있게 되었으면 좋겠음

 

 

 

 

4. 납부관리 (payments.html)

월별 뷰: payYear/payMonth — generateMonthRecords 로 아동×치료 조합별 record 자동 생성

지원유형별 분류: 발본, 발추, 방치, 방치언, 방치작, 방(방과후활동비), 센터

record 구조: id, childId, therapist, support, timeSlot, cycle, monthKey, amount, status, basePaid/extraPaid, paidDate, baseDepositDate, baseDepositorName, extraDepositDate, extraMemo, payMethod, payMemo

저장 안전망:

paid_locks 이중 저장 (마이그레이션 무관 완납 상태 보존)

IDB 백업 (전체 payments)

_skipMigrationOnce — 저장 직후 destructive migration 스킵

id 매칭 실패 시 childId+monthKey+support fallback

미납 현황 요약: 정렬·색상 표기, 완납 우선 판정 (duplicate 대응)

엑셀 내보내기: 월별·아동별

캐시: 월별 record cache, migration cache, paidSnapshot session-once, render HTML cache (M단계 최적화)

 

5. 치료사관리 (therapists.html)

등록: 이름·연락처·전문분야·급여율·재직상태(프리랜서 / 근로)

급여 계산: 회기수 × 단가 (또는 %) — 월별 정산

휴무일 관리: 공휴일 / 개인휴가 / 센터 휴관 → 캘린더 보강 표기 연동

스태프 ID: staff-ids.html, therapist-ids.html — 계정 매핑

 

치료사는 프리랜서 형태로 근무하며, 회기당 급여가 지급됩니다. 따라서 결제된 회기 수와 실제 치료가 진행된 회기 수를 함께 비교·표기하여, 진행된 회기만 급여로 정산되는 구조가 시스템에 반영되어야 합니다.



👉 급여는 실제 진행된 회기 기준으로만 산정되며, 결제는 되었으나 진행되지 않은 회기는 급여에서 제외됩니다.
